Builder: Claude Opus 5.5. Brief: `brief.md` beside this file. Audit it builds on: `research/knowledge/2026-10-26-open-questions.md`. ## What changed

### 1. `data/open-questions.json`
- 493 entries, one per numbered item of the rule base's "## Open questions" sections: **257 open, 135 narrowed, 101 closed**, the audit's counts exactly (checked entry by entry against `merged.json`, `tools/cmp_audit.py`: 0 mismatches).
- Fields: `id` ("TX2 OQ6"), `status`, `closed_on`, `title_he`, `blocks_he`. Generated by `npm run gen:open-questions -w @finance-tool/pipeline` (`packages/pipeline/scripts/gen-open-questions.ts`), using one parse shared with the validator (`readOpenQuestionItems` in `packages/pipeline/src/references.ts`). A struck `~~…~~ Closed <date>` line makes an item closed.
- **The markdown does not mark "narrowed".** The audit's class was tested against a text heuristic and agreed on only 316 of 392 items. So the file keeps the status it has, and a new id takes the audit's class (`merged.json`) when there is one, else `open`. A question that stops being struck goes back to `open`, and the script prints it. The script keeps the hand-written `title_he` and `blocks_he` (re-run checked), and prints any id that left the markdown together with its Hebrew.
- Hebrew title for all **101 questions the site names**, listed by `tools/named.py`: string literals in `site/app`, the guide records' lists and marks, the rule records' text, and the not-covered closures. `blocks_he` is set for 37 of them: blocked checklist rows, exit blockers, tier-2 coverage, playbook steps, the goal form's return constraint, and listed-not-ranked cases. Each title is that question's own line, in plain words, from the audit's `remains` and the item's text. None states an answer (`tools/hebrew_titles.py`).
- Schema `openQuestionsFile` (`packages/schema/src/collections/open-questions.ts`, strict; `closed_on` is set exactly when the status is closed; ids are unique). JSON schema exported. The doc is data-schema §3.15, and the check is §4 item 13.
- Validator: a warning when the file is behind the markdown (an id missing or extra, or a closure the two disagree on). A failure when a guide record lists a question the file has as closed, or blocks on one (`open_questions`, `blocked_by`, a `blocked:` mark). Four tests are added to `packages/pipeline/test/validate.test.ts`.

### 2. The chip reads the data (after the rebase)
- The root loader (`site/app/root.tsx`) adds `openQuestions` from `loadOpenQuestions()` (`site/app/lib/data.server.ts`). PageShell merges it into every page's provenance data, as it does `parameters`.
- Only closed questions and those with Hebrew lines travel with the page: about 190 of the 493. Any other code opens the sheet's general lines, which are true of an open question.
- `IdRef` (`site/app/components/provenance.tsx`) takes `status` and `closed_on` from the data. A closed question opens its closure wherever it is named, with no `closedOn` prop; the prop still wins when it is passed (the not-covered page).
- The sheet keeps its fields (`title_he`, `status_he`, `blocks_he`) and adds:
  - a status line from the data: "פתוחה", or "פתוחה בחלקה: חלק ממנה כבר נענה", from `copy.ts`;
  - a closed question says its date and shows no "blocks" row.
- The id in the sheet's heading no longer breaks across lines (`whitespace-nowrap`). Before, the long titles split "PEN" from "OQ7".
- `guide-signature*.server.ts`: nothing to change. No closed code is named there.
